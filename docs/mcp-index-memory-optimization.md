# 索引内存与性能深挖：变更历史聚合和持久化

日期：2026-09-18。承接 docs/mcp-index-cpu-background.md；本次不包含安装、服务重启或安装包打包。

## 一、现场指标：工作集不能当成私有堆

只读 Win32_Process 采样：

| 进程 | PID | WorkingSetSize | PrivatePageCount（私有提交字节） |
| --- | ---: | ---: | ---: |
| 索引服务 | 27152 | 324018176（309.01 MiB） | 103436288（98.64 MiB） |
| 网络索引代理 | 11304 | 97525760（93.01 MiB） | 49737728（47.43 MiB） |
| Pulse 主程序 | 23900 | 119926784（114.37 MiB） | 151396352（144.38 MiB） |

工作集包含驻留的映射页、共享页和私有页；私有提交包含可能尚未驻留的页。不能把两列直接相减并声称得到精确的文件映射占用。服务快照文件约 655.88 MiB、变更日志约 28.88 MiB，文件大小也不等于实际常驻内存。

未获得对 SYSTEM 服务的页级内存分析，本次没有强行申请调试权限，也没有调用 EmptyWorkingSet、SetProcessWorkingSetSize 或定时收缩堆来制造低工作集数字。

## 二、代码路径盘点

### 已定位并优化

1. src/index/change_tracking.cpp 的 Summaries 原来维护 `ancestor -> identity -> Rollup` 二级哈希表。10 万个文件拥有多个共同祖先时，会同时分配大量“文件 × 祖先”节点。每轮还生成全量路径别名，即使所有事件均已有稳定 file_id。
2. 同文件 Save 使用 PayloadWriter 为整个日志建立连续序列化 vector；扩容时旧、新缓冲区短暂共存。Flush 为避免持锁磁盘 I/O 还会先复制记录快照，因而又叠加一份持久化大缓冲区。

### 已检查但未盲目修改

- src/index/index_engine.cpp 的 AdoptMappedLocked / RefreshQueryShardsLocked 同时映射聚合快照和分卷快照；不同搜索分支会访问分卷或总表。这里有后续减少重复驻留的空间，但直接取消其中一个视图会涉及 FRN、全局节点 ID、排序、增量覆盖和故障恢复，不能仅凭工作集大就关闭映射。
- 同文件 MapIndexFile 验证节点排序表，会触及映射页。这可能影响启动工作集，但不能靠跳过校验来省内存。
- RebuildChildMapLocked 已仅索引 live delta 和 patches，不会把所有基础节点再复制进 child_map_；不是“全盘节点全放哈希表”的问题。
- src/index/index_engine_pinyin.cpp 的拼音辅助 posting 已有 sidecar；现场 sidecar 约 4 MB，本次不砍掉拼音能力。
- Engine::RecordFeed 保留最多 100000 条带路径的记录；ChangeTracker 又独立保留历史，属于有功能目的的数据重叠。后续可以评估紧凑路径存储、字节预算和订阅生命周期，但需保证慢消费者 gap / 补扫语义，不能简单丢掉后台事件。
- ChangeTracker::Details 会先聚合并排序所有匹配记录再裁成最多 200 条，存在改为有界 Top-K 的后续空间。本次未改明细排序/分页算法，以免和摘要/落盘优化扩大耦合范围。
- src/ui/thumbnail_cache.cpp 的 StoreResult 已设 16 MiB / 128 项 LRU 上限，图片上传后会释放 CPU pixels；不能把 UI 的所有私有提交都归咎于无界缩略图缓存。
- 热摘要结果本次基准仅保留约 69 KB；清掉这些缓存收益小、反而增加下次查询重算，因此保留。

## 三、已实施的优化

### 1. 路径别名按需建立

EventAliases 先检查当前时间窗口内是否存在无 file_id 的事件或需要旧版 InitialMtime 抑制的记录。稳定 ID 已足够时直接省掉完整路径别名表；无 ID / 旧格式兼容分支仍按原算法执行。该帮助函数同时被摘要和明细使用。

### 2. 逐文件聚合，避免二维哈希表

Summaries 用顺序链把同一文件身份的事件串起来，再逐个身份聚合它涉及的祖先目录。事件顺序不变，保留删除后创建、重命名、跨目录移动和共同祖先去重语义。

新增 src/index/change_summary_accumulator.h：少量祖先用复用的小 vector；超过 32 项切换哈希查找，避免一个文件在大量目录间移动时退化为平方复杂度。最终 summary 表的元素指针在 unordered_map rehash 后保持有效；整个聚合仍在既有 tracker mutex 下进行。

### 3. 64 KiB 分块序列化

新增 src/index/change_journal_writer.h。字段编码维持现有小端 / UTF-16 v3 格式，使用 64 KiB 栈缓冲；大字符串可以直接流式写入。保存路径仍然是临时文件写完、关闭成功后原子替换；失败继续返回 false，由原有 Flush 重试机制保留 dirty 状态。

本次刻意保留 Flush 的快照复制，以免把磁盘写入移进 tracker 锁内影响查询/事件收集。没有缩短七天保留期、裁掉历史功能或修改用户设置。

## 四、隔离基准与结果

新增 src/bench/change_tracking_memory_test.cpp，目标 pulse_change_tracking_memory_test。仅使用生成的 100000 条记录、128 个目录和独立进程临时目录；不连接生产管道、不读取或覆写用户历史。

测试可执行文件重载普通 new/delete 统计本阶段同时存活的**额外请求堆字节**，另记录分配次数和墙钟耗时。该计数不包括分配器元数据、CRT 内部 malloc、映射页或栈，因此不是现场进程工作集/私有提交。生产代码不包含这些计数器。

每个性能场景前后各运行 3 个独立进程；耗时报告中位数。新增栈缓冲为固定 64 KiB，需另计。

| 场景 | 优化前额外堆峰值 | 优化后额外堆峰值 | 峰值下降 | 耗时中位数（前 → 后） |
| --- | ---: | ---: | ---: | --- |
| 有稳定 ID 的冷摘要 | 82.802 MiB | 11.654 MiB | 85.9% | 1090.650 → 293.825 ms |
| 无 ID 的冷摘要 | 104.775 MiB | 59.736 MiB | 43.0% | 1239.516 → 1051.046 ms |
| Save 序列化 | 43.353 MiB | 598 字节堆 + 64 KiB 栈缓冲 | 序列化内存不再随日志扩容 | 153.782 → 31.624 ms |
| 完整 Flush（含记录快照） | 67.005 MiB | 23.652 MiB + 64 KiB 栈缓冲 | 堆峰值下降 64.7% | 162.372 → 86.653 ms |

稳定 ID 冷摘要约快 3.71 倍。无 ID 场景继续保留完整别名语义，所以收益较小。暖缓存没有改变实现，前后额外堆峰值同为 30910 字节；计时约 0.1–0.5 ms 范围内抖动，不宣称暖缓存显著加速。

原始三次耗时（毫秒）：

- 稳定 ID 冷摘要：前 1090.650 / 1131.688 / 1077.542；后 341.513 / 292.035 / 293.825。
- 无 ID 冷摘要：前 1234.802 / 1239.516 / 1282.447；后 1168.821 / 865.659 / 1051.046。
- Save：前 624.343 / 144.672 / 153.782；后 34.770 / 28.719 / 31.624。
- Flush：前 185.725 / 160.834 / 162.372；后 98.584 / 86.653 / 79.870。

CPU 和磁盘负载、分配计数本身会影响绝对耗时；这是同机隔离微基准，不是安装后常驻内存的承诺。不要把 85.9% 的临时堆峰值下降套到现场 330 MB 工作集。
