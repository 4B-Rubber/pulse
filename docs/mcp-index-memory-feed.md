# 第二轮内存优化：事件队列保留、紧凑存储与低频取证

日期：2026-09-18。承接 docs/mcp-index-memory-followup.md。本轮不安装、不重启运行中的服务。

## 结论和证据边界

已复现并修复一个确定的长期保留问题：索引快照换代后，旧订阅者已被 epoch 检查要求重新同步，但旧代 feed 仍保留最多 100000 条事件及路径。另将 feed 从逐条对象/字符串分配改为分块存储，避免已追平消费者每次扫描 10 万条历史。

尚未证明上一轮约 460 MiB 工作集 / 219 MiB 私有提交波峰的具体来源。新版本增加低频分项采样，供下一轮部署后取证；不宣称这次修改已解决整个服务的常驻内存问题。

本轮仅只读查看过生产历史文件的长度和前 8 字节：v3、100000 条、29087924 字节。没有读取/输出用户事件路径、复制用户历史作为基准或改动生产索引。后续测试均为生成数据或独立目录。

## 代码发现

- Engine::AdoptMappedLocked 原先只增加 feed_epoch_，未释放 feed_changes_。ReadFeed 在锁内先校验 epoch，旧订阅者不能继续消费旧代。新订阅通过 epoch=0 握手从当前 feed_sequence_ 开始，因此已失效旧代队列不应跨快照继续占用内存。
- RecordFeed 原先按值接收 ChangeRecord，又放入 std::deque，路径会复制到每条事件。ReadFeed 从队首逐条跳过旧 ID，即使消费者已经追平也遍历全部记录。
- ChangeTracker 的持久历史与 feed 是不同用途的数据，本轮没有通过删除历史、缩短保留期或停止后台收集来省内存。
- 总索引与分卷映射仍参与实际查询；本轮不删除映射视图或跳过校验。新增计数会分别报告两者映射文件字节数，但不把文件字节数当作驻留 RAM。

## 实施内容

### 1. 正确释放旧代 feed

成功 AdoptMappedLocked 时，在原有 engine 独占锁内增加 epoch 并清空旧 feed；事件序号继续单调递增。失败的提交不触发 Adopt，不丢弃仍有效的队列。没有在未统一持有 engine 锁的 GapFeed 路径直接清容器，以免引入并发问题。

新增 --feed-only 回归先在旧生产代码上运行：只有“snapshot replacement releases unreachable old-generation feed”失败，其余分页/缺口/重同步/历史保留检查通过。接入优化后全部通过，证明修复针对已复现问题，而不是仅根据工作集推测。

### 2. 分块紧凑事件队列

新增 src/index/change_feed_history.h：默认 64 KiB 页，连续存放固定元数据及原始 wchar_t 字符串内容。长记录可单独使用更大的页，读出时才构造返回页的 ChangeRecord。

- 仍保留最近 100000 条，不引入额外字节截断或缩短慢消费者窗口。
- 逐条淘汰，完整页释放；仅首尾页可能保留部分未用空间。
- 按页最后 ID 二分定位，再扫描页内记录，避免每轮从队首扫描全部事件。
- 保留 ID、时间、file_id、类型、目录标志、来源、当前/旧路径；没有路径规范化或有损压缩。
- 仅内存表示改变，IPC、磁盘 v3 格式和搜索排序不变。

### 3. 低频内存采样

新增 src/index/index_memory_probe.h，扩展既有 pulse-index-timing.jsonl 的 memory 字段，原 stages 字段仍保留，原日志轮转上限和写入周期不变。无新线程、无分配器钩子、无强制工作集裁剪。

采样点：change_flush_before、change_flush_snapshot（副本已建立）、change_flush_after（副本已释放）、merge_before、merge_flattened（合并快照仍存活）、timing_flush（日志写入边界，并非承诺空闲状态）。历史批量写入仍遵守 60 秒门限，磁盘 I/O 仍在原 tracker/index 锁外。

低频报告 feed 记录数与页容量、历史记录数与记录数组容量、落盘副本记录数、总表/分卷映射文件大小、增量节点/patch 数量，以及各采样点的工作集和私有提交。

解释限制：

- 数值是全进程采样，包括其他线程，不能仅凭某个前后差值排除并发分配影响。
- max_* 是该采样点的历次最大值，不是连续捕获的进程峰值；不同点的最大值可能来自不同次操作，不应直接相减归因。
- history_vector_capacity_bytes 不包含路径字符串外置缓冲或分配器元数据；feed_page_capacity_bytes 不含 deque 元数据。不能把这些分项当成完整堆账单。
- aggregate_mapped_file_bytes / shard_mapped_file_bytes 是映射文件大小，不是驻留页统计。containers_tick 和 history_tick 标识不同分项的采样时刻。

## 隔离 A/B 基准

新增 pulse_change_feed_memory_test：同一基准包含原 deque 实现和新实现，各模式独立进程，3 次重复。输入在计数基线前生成；统计普通 C++ new/delete 请求字节，不包含 malloc/分配器元数据、栈、映射页，也不是服务工作集。

混合路径包含约百字符目录、中文与部分旧路径；短路径模式使用 C:\x。插入 100000 条后测保留，再插入 100000 条验证滚动淘汰，始终最多保留 100000 条。

| 场景 | 原实现保留堆 | 新实现保留堆 | 下降 |
| --- | ---: | ---: | ---: |
| 混合路径，首次填满 | 40.215 MiB | 33.486 MiB | 16.7% |
| 混合路径，滚动再写 10 万条 | 43.297 MiB | 33.880 MiB | 21.8% |
| 短路径，首次填满 | 10.918 MiB | 5.382 MiB | 50.7% |
| 短路径，滚动再写 10 万条 | 14.000 MiB | 5.384 MiB | 61.5% |

混合路径耗时中位数：首次写入 54.010 → 27.783 ms；200 次各读取最近 512 条，合计 258.242 → 34.078 ms（约快 7.58 倍）；滚动再写 10 万条 34.589 → 14.217 ms。首次填满分配次数 220016 → 1079。

2000 次“已追平、没有新事件”的轮询：原三次 2123.217 / 1983.580 / 1971.314 ms，新三次 0.035 / 0.031 / 0.031 ms。新值极小，仅说明消除了全量扫描，不把这一比例外推为整机 CPU 改善倍数。

混合路径原始追加耗时：旧 62.749 / 54.010 / 43.753，新 48.691 / 27.364 / 27.783 ms。最近页读取：旧 278.290 / 258.242 / 197.315，新 33.617 / 39.551 / 34.078 ms。滚动追加：旧 44.161 / 34.589 / 30.189，新 14.217 / 16.040 / 14.069 ms。

两种容器显式 Clear 后本基准只剩 16 字节被计数的管理开销；旧生产路径的问题是换代时没有执行清理，而不是 deque 本身不能释放内存。实际现场收益取决于换代频率、事件量和路径长度，不能据此承诺工作集下降固定 MiB。

## 验证结果

- Release 构建 pulse、pulse_index、pulse_index_engine_test、pulse_change_tracking_test、pulse_change_tracking_memory_test、pulse_change_feed_memory_test 成功，退出码 0。
- 最终组合验证输出 170 个 PASS、0 个 FAIL，命令退出码 0：Engine --feed-only、--maintenance-only、该模块默认回归；ChangeTracker --flush-only；原内存测试 --check；新 feed 对照及 --probe。
- 新 feed oracle 对照：容量 0/1/61/1000、重复页回收、超过 200000 条记录、512 条分页、单调但不连续 ID、极大游标、长 UTF-16、空字符串、嵌入 NUL、全部事件元数据、清空后重新追加。
- Engine 回归验证换代旧 epoch 缺口、重新握手、序号不中断、新事件可读、持久历史仍保留；原搜索、快照重载、属性回放、排除路径、创建/移动/删除等模块回归通过。
- 诊断验证：批量门限不变，快照三阶段各采样一次；5000 次自身进程内存采样耗时 3.290 ms，普通 C++ 堆分配次数为 0（仅此采样调用，不含 JSON 格式化）。探针 JSON 解析通过。
- 追加运行隔离 --idle-seconds 5：revision 稳定，创建/重命名/删除及时可查，停止及时；当前进程累计 CPU 时间粒度下读数为 0%，不能据此保证所有环境绝对零 CPU。
- 隔离 worker 的实际 timing 文件两行均可解析，保留 8 个 stages、包含 6 个 memory points。此前尝试读取 maintenance 临时目录时目录已被用例清理，改用明确保留日志的 idle fixture 完成解析验证。
- 相关源文件编辑器诊断 0；git diff --check 通过，仅有仓库现有换行策略提示。没有运行全仓库测试。
