# 安装后 CPU 三分钟观测

日期：2026-09-18。关联修复：docs/mcp-index-background-cpu.md；安装包记录：docs/mcp-index-cpu-installer.md。

## 方法与环境

- 观测时间为本机 15:32:54 至 15:35:59，12 个约 15 秒区间，总有效时长 184.264 秒。
- 用 Win32_Process 的 KernelModeTime 与 UserModeTime 累计差计算 CPU 时间；整机 CPU 百分比除以 6 个逻辑处理器。
- 已安装 pulse.exe 和 Pulse.Index.exe 的 SHA-256 均与工作区 build 中对应产物一致，版本 1.0.32。
- PulseIndex 服务处于 Running，PID 27152。网络代理 PID 11304，命令行带 --network-agent。
- 全程未发现 pulse.exe 主程序进程，开始和结束的主窗口列表均为空。因此本次是主程序完全退出场景，不是隐藏驻留或最小化场景。
- 只读观察；未启动或停止用户进程、未重启服务、未改设置、未编译或运行测试。
- 原始采样 JSON 保存在本机临时目录的 pulse-cpu-observation-20260918-19600.json，不纳入 docs。

服务阶段日志覆盖约 180.31 秒，PID 始终为 27152：journal 应用变化 7918 次，增量落盘阶段 12 次；merge、rebuild、recovery 均无新增调用；各阶段错误计数均无增加。事件唤醒 5502 次，仍在处理真实文件变化，不能将环境称为完全静止。

## 判断及限制

- 本次窗口内，索引服务已处于低 CPU 占用状态，没有复现此前持续数个百分点至截图 15.9% 的表现，工作集未出现持续增长。
- 网络代理仍驻留，平均约 0.51% 整机 CPU，明显低于最初投诉的服务高占用；本次不据此承诺网络代理已达到理想空闲状态，也未更改其生命周期。
- 不能将这次下降全部归因于隐藏窗口轮询修复：修复前样本有隐藏驻留的主程序，本次主程序完全退出，且安装过程重启了进程，工作负载并非严格 A/B。
- 隐藏驻留/最小化/恢复的长期行为以及偶发瞬时峰值仍需对应场景观察。当前三分钟结果支持“此刻服务占用正常”，不代表所有场景的性能缺陷已彻底排除。
