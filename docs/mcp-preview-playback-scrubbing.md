# 播放控制修正：文字闪动与 GIF 进度拖动

日期：2026-09-21。接续 `docs/mcp-preview-playback-controls.md`。

## 原因

用户截图显示 `帧 38 / 806 · 70 ms · 播放中` 一行闪动，进度拖动不顺。

1. 旧 `DrawPlayback()` 在 `waiting_for_frame_` 为真时向 GIF 信息插入“正在定位”。自动播放每一帧都要经历等待 / 提交，因此“播放中”之前的内容反复增删，表现为闪动、跳位。这不是应该提示给用户的主动定位状态。
2. 滑块原先使用 `frame_index_ / (frame_count_ - 1)`，它反映已经显示的帧，而不是当前鼠标位置。鼠标必须等异步解码后才看到滑块移动。
3. 每个鼠标移动事件都覆盖 `requested_frame_`，重绘会继续发起不同目标的解码请求；快速拖动容易留下已经过时的中间请求。

## 本次修改

仅修改以下生产文件，未改解码器、缓存、IPC 或视频后端：

- `src/ui/quick_preview_playback.cpp`
- `src/ui/quick_preview_window.cpp`
- `src/ui/quick_preview_window.h`

具体行为：

- 将信息文本生成提取为 `PlaybackInfo()`；GIF 正常等下一帧时不再插入“正在定位”。只有主动拖动期间显示稳定的“拖动定位”。当前帧信息仍对应实际已显示的图像。
- 独立保存连续的鼠标目标比例，拖动时滑块立即使用该比例，不受帧号取整或解码完成时机影响。
- GIF 拖动状态保留在途帧和一个可覆盖的最新目标，不为所有中间位置逐一提交解码。
- 拖动中的解码请求间隔至少 80 ms；滑块跟随鼠标不受这个限速影响。16 ms 调度定时器只负责待处理目标，结束后清除。
- 松手采用抬键事件的最终坐标，并限制在进度条范围内；最终目标优先处理。等待 GIF 最终目标显示期间滑块保持目标位置，不被旧帧拉回。
- 自动播放不能抢在最终定位之前推进；松手后按原状态恢复或保持暂停。
- 定位未完成时切换暂停 / 播放不会丢掉最后目标；立即逐帧时也以用户目标而不是过时的在途帧为起点。
- 重置仅释放播放拖动自己占用的鼠标捕获，不破坏静态图片重绘期间的其它拖拽。

## 定向验证

使用 `src/bench/playback_ui_test.cpp` 链接当前生产对象，执行 `bench_data/playback-regression/run-ui.cmd`，不运行无关历史套件。

- 主程序 `pulse` 定向构建成功。
- 最终窗口 / 播放控制测试 54 项断言通过。
- 模拟截图中的第 38 / 806 帧、70 ms：等待 / 不等待下一帧时，完整信息文本相同。
- 模拟解码停滞期间连续 1001 个拖动位置：滑块逐点跟随；在途目标不变，只保存最后目标。
- 验证松手不回跳、旧解码完成不拉回滑块、最终目标提交、等待期间暂停 / 恢复 / 逐帧、节流与状态清理。
- 用生成的 160×90、806 帧 GIF，通过真实预览解码器执行 60 点拖动，验证滑块与输入一致、最终落到第 806 帧、暂停状态保留。
- 保留相关前后逐帧、捕获丢失、有限循环、视频按钮连通、静态图片切换与组件绘制检查；新增静态图重绘不丢失非播放捕获的检查。
- UI 编辑器诊断未报告 error / warning；测试以 `/W4 /WX` 编译。

### 测试边界与记录

曾有一轮合成拖动的逐点跟随断言失败，其余检查通过；该轮没有逐点输入轨迹，不能断言根因。增加轨迹日志后复查未复现。测试驱动随后明确隔离合成拖动期间本测试窗口队列里的桌面鼠标移动，仅以同步注入坐标为预期输入，避免移动真实用户光标来运行测试。产品窗口的鼠标消息处理未被过滤。逐点跟随断言、异步解码消息处理和失败轨迹记录均保留，最终结果以上述日志为准。

用户目前提供的是截图，而不是原始 GIF。此次长动画测试是生成的独立样本，不代表已复测用户原文件。高分辨率 / 复杂 GIF 的画面定位仍需要解码时间；本次消除滑块等待解码和过时拖动请求堆积，不声称所有 GIF 都能瞬间出帧。组件绘制检查仍遵循前一份记录的边界，不把组件图当作整个应用桌面录像。

