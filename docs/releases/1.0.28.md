# Pulse 1.0.28 内容搜索测试版

内容搜索按任务使用 CPU 和临时正文内存；结束或取消后回收匹配线程、正文缓冲及任务专属文档解析进程。状态栏显示已匹配文件数和检查进度，持续输出结果时保留当前列表。

## 改动

- 查询大正文时最多使用 4 个任务内匹配线程。数据库读取保持同一快照，按原排序交付结果；首个正文同步检查，避免等整个批次才显示第一条。
- 任务队列最多 8 项，排队的 UTF-8 正文预算约 8 MiB，单个超大正文独占队列。此预算不包含解码后正文和其他程序内存，不是进程内存上限。
- 状态栏在候选总数未知时显示活动进度，已知后显示“已检查 / 候选数”和进度条。候选数是本次查询待检查的文件数，匹配数是文件数，不是词语出现次数。完成、取消或错误后收起任务进度。
- 持续追加结果时复用排序索引，减少重复排序和显示位置表写入。排序、过滤与稳定身份保持，先准备页面再替换，避免清空当前结果。
- 新增 PDF 文字层搜索，使用本机 IFilter。实测定位并处理 Windows PDF 过滤器仅支持流式加载的兼容问题；PDF 使用 MTA，Office 保持原有 STA。
- 文件夹直接扫描复用任务专属解析进程，任务返回即结束；已有内容索引的查询不启动解析器。后台建库仍有自己的读取线程和空闲退出机制，持久索引保留在磁盘。

## 实际验证

同一隔离夹具，512 个、每个约 128 KB 的正文，名称排序，3 次运行中位数：

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 短中文、靠前命中 | 303 ms | 140 ms |
| 正文尾部命中 | 962 ms | 462 ms |
| 候选均未精确匹配 | 734 ms | 480 ms |

这是本机合成数据对比，存在调度抖动，不包含初次建库，也不是与 Everything 的完整对比。

- 查询定向检查 74 项通过：顺序、结果上限、大小写、整词、排除词、单一快照、增量、零命中进度及取消。取消实测 37.6 ms。
- 资源采样：线程数 9 → 14 → 9（峰值包含 1 个采样线程和 4 个匹配线程）；工作集 47.58 → 51.30 → 47.60 MB。这里只说明该夹具的任务资源回收，不代表全盘索引常驻占用。
- 20,000 条合成结果、每批 64 条，首批后切换大小降序：追加总耗时 7206 → 2966 ms，单批 P95 45.5 → 16.3 ms，最大值 97.5 → 26.1 ms。追加定向检查 7 项和实时结果存储检查 20 项通过。
- 状态栏实际渲染检查 129 项通过，覆盖未知/已知总数、完成/取消/错误、720/1100 宽度、深浅主题及 100%/150% DPI。截图位于 `bench_data/content-progress-ui/`；这是隔离窗口模型的渲染验证。
- PDF 定向检查 27 项通过：中英文、与 Office 交替解析、无文字层/损坏文件、大小预算、取消、任务结束进程退出、直接扫描及索引后检索。受影响的 Office 集成检查通过。
- 最终主程序重新构建后，应用交互 5 项检查通过，确认列排序保持查询代次和结果存储，搜索中保留列表及计数。日志 `build_realtime/content-interaction-1.0.28.log`。

五个安装程序均已构建并核对版本为 1.0.28，安装包 `dist/PulseSetup-1.0.28.exe` 及同名 `.sha256` 已生成，包含 LumaText 运行时与许可证；未执行安装。安装器保留既有的管理员安装与 HKCU 项提示，本轮未修改安装行为。

日志：`build_realtime/query-baseline.log`、`build_realtime/query-final.log`、`build_realtime/pdf-task-test.log`、`build_realtime/document-regression-test.log`，以及 `bench_data/content-append-before.log`、`bench_data/content-append-after.log`、`bench_data/content-store-realtime.log`、`bench_data/content-progress-ui-run.log`。

## 测试范围

安装后可用同一关键词连续切换名称/大小升降序，观察列表保留、匹配数和任务进度，再测试带文字层的中文 PDF。既有内容文件夹中的 PDF 会在协调扫描时纳入索引；首次提取仍需要时间。

PDF 依赖本机兼容过滤器；本版不做 OCR，不提供 PDF 页码定位。索引范围不完整、文件被占用或文件无法提取时，仍应以界面状态为准。完整多卷压力、历史文件操作长尾和稳定多选恢复仍在待办范围；本版不宣称完成全部实时搜索重构或全面超过 Everything。
