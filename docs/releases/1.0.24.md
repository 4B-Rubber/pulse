# Pulse 1.0.24

- Content searches no longer stop at 10,000 matches. Indexed and explicit transient content queries can return the complete matching set. Filename, path, extension/type, size and modification-time ordering is performed over the full query, including rows not yet displayed.
- Content results stream into a private temporary SQLite result store on the client worker. The first hit remains publishable immediately; progress updates coalesce instead of accumulating hit vectors on the UI thread. Arbitrary scrollbar jumps read the requested disk page directly. The result-page cache holds at most eight 256-row pages, with the existing separately bounded row-presentation cache.
- The header distinguishes searching, completed totals and canceled/incomplete counts. Matches remain usable while the query continues. Cache failures are surfaced as incomplete results.
- Mouse selection, keyboard navigation, cross-page selections, select all, wildcard selection and inline filtering use global result indices. Explicit operations resolve their selected files in the background, including unloaded pages; their temporary metadata is released after the command. Focus-only preview resolves one file even with a large selection. Pending commands are invalidated by a changed selection, replacement query or exit.
- Refresh can restore a selected file by its full path without scanning all result rows on the UI thread. Clearing/exiting search releases its result source and preserves the existing original-address restoration behavior.

Validation:

- Built only the affected app, content agent and focused paging/content-index test targets; compiler logs contain no new warnings or errors.
- The focused paging backend test passes all 22 checks using 12,050 actual indexed text documents: complete counts, six global descending orders, first-hit streaming, arbitrary page reads beyond 10,000, bounded cache, full filtering, cross-page/all-row resolution, stale-client cancellation and normal temporary-store cleanup.
- The isolated native UI fixture passes with 15,050 disk-backed hits. Checks include first-page interaction while counting, selecting row 12,002 with real mouse messages, reaching the final row, resolving three separated rows and all 15,050 rows, background size totals, wildcard matches at the unloaded tail, filtering, path-based selection restoration, stale-action rejection and canceled-count labeling. A final check confirms focused-only actions read one file under select all.
- Native screenshots of running, beyond-10,000, filtered and final-row states were captured and inspected in dark 150% and light 200% at 1440 x 900 physical pixels. The final focused-action regression was rerun in dark 150%. These are actual renderer captures; their hosted native editor text can be omitted by the compositor snapshot mechanism.
- The related content-latency regression passes 15 checks, including repeated/adjacent cancellation, first-hit delivery and transient scans. The 256-document isolated persistent-client requests complete in 15–16 ms; this does not measure the user's full index.
- The focused history-menu UI regression and the existing scoped exit-origin regression both pass. No full selftest or unrelated suite was run.

Normal browsing memory is bounded by page/cache limits rather than the number of hits. Disk usage grows with the result set. An explicitly requested bulk operation may temporarily allocate metadata/path lists proportional to its selection, as required by the existing file-operation interfaces; this memory is released afterward. Temporary cache cleanup was verified on normal query-owner release, not forced process termination.

Existing uncommitted changes are preserved. This release does not migrate the persistent content index, rebuild it, or add document-extraction dependencies.
