# Pulse 1.0.29：实际文档漏搜与输入框闪烁修复

本轮以用户截图中的 `content:3d3s` 为对照，通过 voidtools 官方 ES 工具只读导出本机 Everything 的 52 项结果，再验证同一批文件。未修改用户原文件、实际内容索引或配置。

## 查明的问题与修复

- **DOC/XLS 空正文**：旧 IFilter 初始化参数使本机 OffFilt.dll 直接返回正文块结束，Pulse 将其当作成功的空正文。增加 `IFILTER_INIT_APPLY_INDEX_ATTRIBUTES` 后，实际 27 个 XLS 和 5 个 DOC 全部提取并匹配成功；STA/MTA 对这个问题没有改变结果。
- **大文档被大小上限排除**：对照中一份 DOCX 为 99,172,206 字节，两份 PDF 各 85,491,320 字节，超过此前 64 MiB 限制。现在文档有独立的默认 512 MiB 输入预算，普通文本仍为 64 MiB；OOXML 输入包大小与实际提取 XML 的累计 64 MiB 预算分开。显式设置的更小文档预算仍有效。
- **旧空缓存不会自行恢复**：提取器版本纳入文档版本标识，升级后自动重新提取旧 Office/PDF 缓存，保持文件身份和配置；普通文本不强制重新提取。
- **尚未建完的索引**：只读检查确认范围已包含 C–G 盘，但当时库里只有 15 个 PDF、7 个 DOCX，截图指定的几份文档尚未入库。共享扫描原先处理完一个根的 1024 条记录才轮到下一根，慢文件拖住其他根；改为有界分页、各根轮转准入。
- **扫描中计数冻结**：状态原先只在整轮结束时更新已入库总数，已有数千记录仍可能显示 0。现在开始时和扫描中每 500 ms 更新已提交计数；使用 `(root,size)` 覆盖索引，一次分组统计，锁外查询后短锁发布，避免每次读取正文所在表页。
- **搜索词闪烁**：父窗口每次绘制都给真实 LumaText 输入框重复设置相同边距，触发重绘包装并短暂隐藏文字控件。改成仅在边距变化时设置，保持文字、选区与焦点。
- 建库状态会持续更新到搜索提示中，不再一直停留在“仅搜索已加入索引的文件夹”；扫描时明确显示建库及已入库数量。

## 安装后行为与边界

已生成 `dist/PulseSetup-1.0.29.exe`（4,986,244 字节）及 `.sha256`，五个程序版本均为1.0.29，包含LumaText运行时和许可证。安装器编译成功，保留既有管理员安装/HKCU提示；未执行安装。

无需清空内容库。升级后会自动重新提取旧文档并继续补全尚未扫描到的文件，结果通过现有实时订阅补入；首次补全仍需时间，不等同于安装后立刻完成全盘查询。新增统计索引也有一次性建立成本。

PDF 仍依赖本机过滤器，支持文字层，不做 OCR；文档解析保留进程内存、输出量、超时和取消边界。此次证明的是上述 52 个实际文件的覆盖及输入框修复，不宣称所有文件格式、所有磁盘或所有时延都超过 Everything。
