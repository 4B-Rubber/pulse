# Pulse 1.0.27 内容搜索体验修复

- 升降序在后台重排已有结果，不重新匹配正文；连续切换只应用最新排序，后续流式结果和实时增量沿用当前排序。
- 新页面缓存准备好后再替换已显示页面，避免每批更新先清空列表。
- 标题显示匹配文件数与搜索进度；这里统计的是匹配文件数量，不是正文中词语出现次数。
- 文件占用提示与查询状态分开，原文件恢复并提交后清除当前占用错误。
- 排除 Pulse 自身数据，避免新输入的搜索词命中搜索历史；已有索引中的自身记录也在查询时过滤。

## 验证

- 修正编译输出编码并重新生成依赖配置，干净构建安装目标和相关测试通过。完整依赖构建显示现有第三方 FreeType/SQLite 编译警告；本次应用代码增量构建无新增警告。
- `--store-realtime` 20 项通过，覆盖最新排序、流式追加、实时更新、缓存持续可读及过滤保持。
- `--store-sort-latency`：20,000 条合成结果，降/升/降排序后台完成分别 31.221 / 44.516 / 29.850 ms，提交调用 0.004–0.005 ms；不包含真实磁盘正文解析时间。
- 应用交互检查通过：点击列排序不更换结果存储、不改变查询代次，匹配数和扫描进度可见。
- 文件占用恢复与内部数据排除两个独立夹具通过；没有清理或修改用户实际索引。
- 1100 和 720 像素宽度的隔离界面截图已检查：匹配数、扫描进度、占用提示及列表可见。初版截图辅助程序缺少快照初始化而失败，补齐后通过；不是把失败记作通过。
- 安装包 `dist/PulseSetup-1.0.27.exe` 已编译；未执行安装。截图位于 `bench_data/content-experience-1.0.27/`，日志位于 `build_realtime/`。

本次没有重跑无关的完整历史套件，也没有重新声称此前文件操作时延全部达标。

## 实测建议

使用相同正文关键词，反复切换名称/大小的升降序，观察列表和匹配数；再修改一个匹配文件，确认结果更新时不会先整页消失。文件仍被其他程序独占时，部分结果可以暂时不完整，界面应说明文件占用而非笼统报告搜索失败。

本版本不宣称完成全部实时搜索重构；完整多卷压力、所有格式和稳定多选恢复仍在待办范围。
