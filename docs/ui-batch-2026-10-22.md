# 2026-10-22 UI 批次：预览、主题、进度与标题栏

这一批改动来自同一天的使用反馈：一个被合并丢掉的回归修复（编辑框输入法光标），加四个"让用户自己选"的开关或行为调整。全部是本地 `dev` 线的增量，没有升版本号、没有改发布日志。

## 1. 找回 IME 光标守卫（回归修复）

- **现象**：在文件名编辑框里用 TSF 输入法（微信输入法）提交组字后，插入点跳回开头，后续字符插到最前面——`demo` 再打 `1` 变成 `1demo`。
- **根因**：编辑框隐藏了原生光标、由 LumaText 自绘，TSF 桥提交后会来问"插入点在哪"，被告知 0。2026-09-23 的 `1766b14` 曾在 `src/ui/edit_host.cpp` 里加过守卫，10-03 合并上游 1.0.53 的重建（`d8ba19a` 那条线）把这一整段丢了；`0f3905f`（#116，"组字从选中主干开始"）只覆盖微软拼音那条路径，盖不住 TSF 这次回写。
- **现在**：一轮提交后 2 秒内，丢弃把插入点挪到提交位置**之前**的 `EM_SETSEL`；点击、方向键、Home/End、PageUp/PageDown、Backspace/Delete/Insert、焦点变化结束这一轮（普通字符与鼠标移动不结束）。`WM_SETTEXT` 重写全文时恢复光标：文本没变还原原选区，变了放到改动区末尾——EDIT 每次 `WM_SETTEXT` 都会把光标打到 0。我们自己恢复光标那次 `EM_SETSEL` 由 `g_restoring_caret` 排除，不会被守卫吞掉。
- **诊断**：`PULSE_EDIT_TRACE=<文件>` 时守卫把 `guard drop/keep/armed-first` 写进该文件（默认不落盘），用于判断"守卫没生效"还是"别处又在挪光标"。
- **用例**：`src/bench/child_edit_test.cpp` 新增 5 条——改写全文后光标在改动区末尾、重复写回保留原选区、提交后光标在字尾、提交后把光标写回 0 被丢弃、按方向键后允许回头。

## 2. 空格预览：没选中时预览指针下那一行

`settings` 里「预览方式」只控制**悬停卡片**弹不弹，空格预览本身一直要"有选中项"，于是切到"仅空格预览"后悬停文件按空格毫无反应。现在空格的目标按这个顺序取：

| 指针在文件行上 | 有选中项 | 空格预览谁 |
| --- | --- | --- |
| 是 | 否 | 指针下那一行（并选中它） |
| 任意 | 是 | 选中项（指针不抢） |
| 否 | 否 | 无目标，和以前一样什么都不做 |

- 实现：`OpenHoveredRowInQuickLook()`（`src/app/app_hover_preview.cpp`）在 `OpenHoverPreviewInQuickLook()` 之后兜底，`src/app/app_input.cpp` 的 Space 分支串起来；跨窗格会先切焦点，走的是与悬停卡片"空格打开"同一条 `SelectOnly + EnsureRowVisible + ToggleQuickPreview`。
- 文案：设置项「空格预览」改为「仅空格预览」，说明改为「悬停时不弹卡片；选中文件，或把指针停在文件上，按空格键预览」（`src/ui/settings_layout_sections.h`）。

## 3. 主题按钮三态

标题栏那颗主题按钮以前是两态：点一下就在浅色/深色之间取反，`theme_mode=0`（跟随系统）一点就丢，只能回设置里选回来。现在按"跟随系统 → 浅色 → 深色 → 跟随系统"循环，图标直接表示状态：半圆 = 跟随系统、太阳 = 浅色、月亮 = 深色；悬停提示写「主题：跟随系统 / 浅色 / 深色」。

- 从"跟随系统"出发的第一步**一定改变明暗**（系统浅色先去深色，系统深色先去浅色），避免默认状态下第一次点击像没反应；唯一可能"画面没变"的一步是切回"跟随系统"时恰好与当前一致，此时图标会变回半圆、提示也会写明。
- 入口：`ToggleTheme()`（`src/app/app_commands.cpp`）+ `vm.theme_mode`（`src/ui/ui_renderer.{h,cpp}`）+ `kIconThemeLight/Dark`（`src/ui/ui_renderer_internal.h`）+ 无图标字体时的手绘兜底（`src/ui/legacy_icons.h`）。

## 4. 文件操作进度可改成弹窗

以前复制/移动/删除的进度只画在状态栏那个胶囊里，细节窗口要点胶囊才出来，看起来像"卡住了"。新增设置「进度显示在弹窗中」（`app.json` 键 `operation_progress_window`，默认关）：

- 关（默认）：保持状态栏胶囊，行为不变（点胶囊仍可调出同一个窗口）。
- 开：操作开始约 400 ms 后，那个进度窗口自己弹出来（不抢焦点、居中在窗口上），完成后 600 ms 自动关；**同一个操作不再同时出现在状态栏胶囊里**（`vm.status.task_hidden`，状态栏把这段空间还给选中项/提示文字）。
- 开状态下，操作中手动关掉窗口后，本次任务不再自动弹（沿用 `operationDismissedTaskId`），**胶囊会回来接替**——否则关掉窗口就没有任何进度可见、也没法再把它叫回来；点这颗胶囊仍会重新弹出窗口。
- 400 ms 阈值是为了让"小文件秒完成"的复制不闪一下窗口。应用自身的更新进度（`task_is_update`，居中的那条）不受这个开关影响。

## 5. 紧凑标题栏

新增设置「紧凑标题栏」（`compact_title_bar`，默认关）。打开后：

- 只隐藏标题栏左侧的 **Pulse logo 与「Pulse 文件管理器」文字**；侧边栏折叠按钮**保留**，移到窗口最左边（原来品牌的位置），一次点击照样能收起/展开（Ctrl+B 也仍然有效）。
- 标签条起点改为"折叠按钮右边缘 + 4 DIP"（有窗口身份名字时排在名字后面），省下来的就是品牌那段空间。
- 多窗口场景：标题栏放不下窗口名字时，颜色点画在折叠按钮右下角，且**不占点击**（避免抢按钮）；窗口名字仍在任务栏标题里。
- 取舍：紧凑模式下标题栏左侧没有空白可拖窗口，拖动要靠最后一个标签右边的空白；标签铺满时那点空白会很小。

## 设置项一览

| `app.json` 键 | 默认 | 设置页位置 | 作用 |
| --- | --- | --- | --- |
| `preview_trigger` | `0`（悬停卡片） | 通用 → 快速预览 → 预览方式 | `1` 只保留空格预览（文案「仅空格预览」） |
| `operation_progress_window` | `false` | 通用 → 文件列表组末尾 | 文件操作进度用弹窗而不是状态栏 |
| `compact_title_bar` | `false` | 通用 → 外观末尾 | 隐藏标题栏品牌，折叠按钮移到最左 |

三个键都随 `app.json` 持久化；紧凑标题栏切换后立即生效（新增 `SettingsEffect::TitleBarChrome` → `renderer.SetCompactTitleBar()`），多窗口同步，不用重启。
