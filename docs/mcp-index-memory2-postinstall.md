## 已确认的代码缺陷

位置：src/index/usn_stream.h，UsnStream::Read 第 45、59、62–63 行；消费侧为 Take 第 20–30 行。它位于上一轮优化的 ChangeFeedHistory 上游：

磁盘 USN → 原始 packet 队列（本次发现）→ 索引主线程处理 → 上层 feed / 持久历史。

原实现每次读取都创建 `std::vector<BYTE> packet(256 * 1024)`。收到数据后仅调用 `packet.resize(received)`，随后将 packet 移入 packets_。resize 缩小 size 不释放 capacity，move 保留原缓冲。即使只收到很小的数据，每个排队包仍持有 256 KiB 容量。

同时，bytes_ 与 64 MiB 上限仅累计 packet.size()，没有累计实际容量。这不是“泄漏已证明”，而是确定的缓冲容量放大及预算口径错误：逻辑字节限额无法约束实际保留容量。

主线程在 Worker 中先执行 changes_.Flush(false, ...)，随后才调用 CatchUpVolume/Take。Flush 期间采集线程继续读取并入队；源码说明也明确采集不会因合并/写盘等待。因此该缺陷能在消费暂停期间把小包积压放大为显著内存波峰，消费后又回落。这与本轮相位和涨落形态吻合。

但本版本没有记录 UsnStream 各队列的包数/容量，尚不能给出它对每次现场波峰贡献的精确 MiB，也不能证明它是唯一原因。

## 后续修复方向与边界

优先修正 USN 原始队列，而不是继续削减历史或强制清工作集：

- 将异步 I/O 缓冲与排队包分离，复用读缓冲，只保留已收到的有效字节。
- 按实际保留容量实施队列预算，并记录原始队列包数、有效字节、容量及高水位。
- 保留 cursor 顺序、overflow/gap 语义和 CancelIoEx/退出行为；覆盖小包洪峰、满包、消费/生产交错、溢出、停止等测试。
- 修复后再做相同运行条件对照，确认现场波峰贡献；不以隔离复现直接宣称实机波峰已消除。
